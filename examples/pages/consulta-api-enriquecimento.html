Enriquecimento API com cache por request

Contrato fechado para listar pedidos e resolver dados de cliente, produto ou outro relacionamento externo sem repetir chamada para o mesmo identificador dentro da mesma leitura.

Indice Manual

Quando usar

Use em entidades api quando a listagem vem de uma operacao externa e um ou mais campos dependem de outra operacao da mesma fonte.

  • Pedido retorna cliente_id, mas nao retorna cliente_nome.
  • Mesmo cliente aparece em varias linhas.
  • O runtime precisa buscar cada cliente uma vez por request e reaproveitar o resultado.

Modo batch

{
  "api": {
    "jsonPath": "cliente_nome",
    "lookupResolver": {
      "operationCode": "clientes_batch",
      "sourceField": "cliente_id",
      "requestParam": "ids",
      "mode": "batch",
      "responseItemsPath": "items",
      "matchField": "id",
      "valuePath": "nome"
    }
  }
}

Modo por valor

{
  "api": {
    "jsonPath": "cliente_nome",
    "lookupResolver": {
      "operationCode": "cliente_detalhe",
      "sourceField": "cliente_id",
      "requestParam": "id",
      "mode": "per_value",
      "responseItemPath": "$",
      "valuePath": "nome"
    }
  }
}

Como o runtime trabalha

  1. Executa a operacao principal da entidade API.
  2. Mapeia os campos base da linha.
  3. Agrupa os identificadores distintos do sourceField.
  4. Chama a operacao de lookup uma vez por conjunto ou uma vez por valor distinto.
  5. Reaproveita o resultado nas linhas repetidas antes de filtrar e ordenar.

Limites

  • So funciona com operacoes cadastradas na propria fonte API.
  • Nao aceita URL livre, SQL, template ou JavaScript vindo do metadado.
  • O cache atual e por request do backend, nao um cache global persistente.
