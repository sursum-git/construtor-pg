Minimo de entidade no runtime

Exemplo preenchido para criar a entidade `produto` com tabela fisica, metadados do construtor, situacoes opcionais, tela e endpoints fechados.

Indice Abrir tela

So existir classe Doctrine ou tabela nao basta. Para o frontend dinamico funcionar, o backend precisa destes cadastros minimos.

Ordem Arquivo O que preenche
1 01-create-table-produto.sql Tabela fisica PostgreSQL.
2 02-builder-entity.json Registro da entidade `produto` em `builder_entity`.
3 03-builder-fields.json Campos em `builder_field`, incluindo chave primaria e tipos.
4 04-screen-definition.json JSON publicado da tela `cadastros.produtos`.
5 05-runtime-endpoints.json Endpoints `read`, `get`, `create`, `update` e `delete` com `handler="entity.crud"`.
6 06-test-runtime.http Chamadas HTTP minimas para validar backend e frontend.
7 07-builder-situations.json Situacoes e transicoes opcionais da entidade.

1. Tabela fisica

Arquivo: examples/minimo-entidade/01-create-table-produto.sql

CREATE TABLE IF NOT EXISTS produto (
    id BIGSERIAL PRIMARY KEY,
    codigo VARCHAR(30) NOT NULL,
    nome VARCHAR(160) NOT NULL,
    status VARCHAR(20) NOT NULL DEFAULT 'EM_DIGITACAO',
    preco NUMERIC(14, 2),
    created_at TIMESTAMP(0) WITHOUT TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP(0) WITHOUT TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP
);

2. Entidade no construtor

Arquivo: examples/minimo-entidade/02-builder-entity.json

{
  "code": "produto",
  "name": "Produto",
  "entityType": "persistence",
  "tableName": "produto",
  "status": "published",
  "situationEnabled": true,
  "situationFieldCode": "status",
  "metadata": {
    "screenId": "cadastros.produtos",
    "primaryKey": "id",
    "situation": {
      "enabled": true,
      "field": "status",
      "initial": "EM_DIGITACAO"
    },
    "audit": {
      "enabled": true,
      "doctrineClass": "App\\Entity\\Produto"
    }
  }
}

4. Tela entregue ao frontend

Arquivo completo: examples/minimo-entidade/04-screen-definition.json

{
  "screenId": "cadastros.produtos",
  "pageType": "crud",
  "status": "published",
  "definition": {
    "program": {
      "id": "cadastros.produtos",
      "title": "Produtos"
    },
    "dataSource": {
      "api": {
        "read": { "endpointId": "read", "method": "POST" },
        "create": { "endpointId": "create", "method": "POST" },
        "update": { "endpointId": "update", "method": "POST" },
        "delete": { "endpointId": "delete", "method": "POST" }
      }
    },
    "runtime": {
      "entityCode": "produto",
      "programId": "produtos-crud"
    }
  }
}

5. Endpoints fechados

Arquivo: examples/minimo-entidade/05-runtime-endpoints.json

[
  {
    "screenId": "cadastros.produtos",
    "endpointId": "create",
    "handler": "entity.crud",
    "enabled": true,
    "config": {
      "entityCode": "produto",
      "programId": "produtos-crud",
      "operation": "create"
    }
  }
]
